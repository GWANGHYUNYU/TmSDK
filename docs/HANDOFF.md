## 2. 현장과 장비

```
[TMC160F × 2]  160×120, 8.775 fps, Y16 (16-bit 라디오메트릭)
   ├─ 192.168.0.151  무송풍 구역  ← RGB 카메라가 옆에 매직암으로 고정
   └─ 192.168.0.152  송풍 구역    ← RGB 없음
        │ PoE
   [스위치] ─ [Ubuntu 22.04 PC]  ubuntu_python_stream/multi_cameras_multi_roi_y16.py
```

딸기. 화분이 **삼각(A형) 거치대에 경사 배치**되어 흰 홈통에 일렬로 놓이고,
잎·화방이 바깥으로 늘어집니다. 카메라에서 본 캐노피 거리가 층마다 달라
**420 / 700 / 1000 mm** 세 층으로 나눕니다. LED 측면 조사,
**점등 08:01 / 소등 18:01** (일사 데이터로 6일 연속 확인).

이 경사 배치가 GSD 문제의 원인이면서, 동시에 과제가 겨냥한 «국소 공조 편차»의
전형적 사례입니다.

|---|---|

| 정합 오차 | 중앙 **0.93 px**, 90 % **1.63 px** |

### 반드시 지켜야 할 좌표 규약 — 여기서 제일 많이 틀립니다

```
H(d) 는  「원본 RGB 파일 좌표」 → 「180° 돌린 열화상 좌표」  로 맵니다.
```

- **RGB 영상이 물리적으로 뒤집힌 쪽**입니다. 보기용으로만 180° 돌리고,
  **저장은 원본 파일 좌표**로 하십시오.
- 그래서 «RGB 반전» 과 «열화상 rotated» 를 나란히 놓으면 **위아래가 반대로
  보입니다. 정합이 틀린 게 아닙니다.** 나란히 볼 때는 양쪽을 같이 돌리십시오.
- 추측하지 말고 확인하십시오 — 마스크 적합도로 네 방향을 비교하면
  현재 방향이 모든 슬롯에서 최고(08:00 기준 1.218 vs 상하반전 1.038)입니다.

## 5. 측정 결과 — 무엇이 확인됐나

### 5-1. ★ 송풍 효과가 개체 단위로 확인됩니다

같은 날 잎 평균 (℃) — `.151` 무송풍 / `.152` 송풍

| 날짜 | 점등 차이 | 소등 차이 |
|---|---|---|
| 09-19 | **+0.55** | +0.04 |
| 09-20 | **+0.55** | +0.07 |
| 09-22 | **+0.45** | +0.01 |

**«밤에 사라진다» 가 핵심입니다.** 카메라 오프셋이나 화각 차이라면 밤에도
남아야 합니다. 사라진다는 것은 점등 중 기류가 만든 실제 온도차라는 뜻입니다.

### 5-2. 층별 편차 — 두 카메라가 독립 재현

점등 중, 1000 mm 층이 그 구역 잎 평균보다:
`.151` **+0.35~+0.45 ℃** · `.152` **+0.59~+0.78 ℃** — 11일 내내 «먼 층이 더 뜨겁다».

### 5-3. 개체 간 편차 — 이 과제가 겨냥한 값

| | 점등 | 소등 |
|---|---|---|
| `.151` | 0.40~0.47 ℃ | 0.13~0.26 ℃ |
| `.152` | 0.54~0.65 ℃ | 0.17~0.28 ℃ |

점등 중이 소등 대비 **2~3배**. 두 구역, 11일, 전혀 다른 두 마스크 방식에서
모두 같은 방향입니다. 하루 안에서도 **점등 직후에 가장 크고** 낮 동안 줄다가
소등 무렵 다시 튑니다.

## 6. 아직 못 하는 것 — 솔직한 목록

| | 상태 | 막는 것 |
|---|---|---|
| **절대 엽온 정확도** | ❌ | 오차 예산 0.56 ℃ 와 신호(0.4~0.65 ℃)가 **같은 크기**. 개체 **간** 비교는 유효, 절대값은 아님 |
| `.152` 의 층 구분 | ⚠ 검증 안 됨 | 눈으로 넣은 값. RGB 매칭이나 `.152` 스테레오 필요 |
| `.152` 의 꽃·딸기 | ❌ 불가 | 열화상으로 안 갈림 (꽃 66 % · 딸기 44 %) |
| 열화상 단독 분할 모델 | ❌ 미착수 | 자동 라벨 파이프라인이 먼저 |
| GSD 단일값 | ❌ | 경사면이라 행마다 깊이가 다름. 행별 함수가 필요 |

### 가장 큰 기회 — 엽온센서가 화면에 잡혔습니다

`.152` 어노테이션에 **접촉식 엽온센서 2개**가 들어 있습니다
(적합도 2.86 / 1.32, 배경보다 +0.78 / +0.48 ℃). **참조면이 화면 안에 있다는
뜻**이라, 그 센서의 기록값을 받아 오면 절대 오프셋을 바로 물을 수 있습니다.
중간보고에서 미해결로 남긴 «야간 잎−기온 +1.98 ℃ 과대» 의 원인도 여기서
갈립니다.

### 운영 문제 둘

1. **RGB 노출이 무너져 있습니다.** 08:25 이후 화소의 16~20 % 가 포화합니다.
   지금은 **하루 25분치**(08:00 대)만 분할에 쓸 수 있습니다.
   → 노출 고정(EV −1~−2) 또는 게인 상한.
2. **녹화가 조용히 멈춥니다.** `.151` 이 09-18 19:30 에 빠진 뒤 닷새간 `.152`
   만 남은 적이 있습니다. 원인 둘을 고쳤지만(아래), 근본 원인(왜 `.151` 만
   멈추는가)은 네트워크·전원·카메라 중 어느 것인지 아직 모릅니다.
   → 랜선·PoE 포트를 서로 바꿔 보면 한 번에 갈립니다.

### 측정과 추측을 섞지 말 것

- **분류 규칙의 출력을 «측정값» 이라고 불렀습니다.** 휴리스틱으로 분류해 놓고
  "75 % 가 LED 바 때문"이라 적었는데, 실제로 재 보니 **0 %** 였습니다.
- **약한 근거를 확정으로 승격했습니다.** 자기상관 0.05~0.25 를 근거로
  주기를 확정했다가 뒤집혔습니다.
- **방향·순서를 가정하지 마십시오.** 투영 방향, 층 순서, 슬롯 시각 순서 —
  전부 한 번씩 틀렸고, 전부 **재 보니 답이 나왔습니다.**

### 지우기 전에 수치부터 남길 것

탈락 65건을 진단 수치 없이 지운 탓에 나중에 원인을 물을 수 없었습니다.
그래서 캘리브레이션 산출물을 정리할 때는
[calibration_verification_log.md](calibration_verification_log.md) 를 먼저
썼습니다. **같은 순서를 지키십시오.**

### 지표를 쓰기 전에 «지금 잴 수 있는 조건인가» 를 먼저 가를 것

- 야간에는 잎이 공기와 평형이라 **열화상에 잎 경계가 아예 없습니다.**
  적합도가 1 미만으로 떨어지는데, 이것을 «마스크가 틀어졌다»고 읽으면 틀립니다.
- 한 슬롯에 조명·사람이 들어오면 편차 배율이 끌려가 **멀쩡한 개체가 0.86 으로
  나옵니다.** 같은 날 깨끗한 슬롯에서는 1.93 이었습니다.
- **임계를 딱 떨어지는 값에 두지 마십시오.** 0.97 과 1.00 을 «실패/성공» 으로
  가르면 안 됩니다. 띠(확인/보류/미확인)로 나누십시오.

### 조용히 빠지는 것을 조심할 것

| 사고 | 증상 | 교훈 |
|---|---|---|
| 녹화가 두 폴더에 나뉨 | 103슬롯이 **말없이** 빠짐 | 재귀로 훑기 |
| `cv2.imwrite` 한글 경로 | **0장 저장하고 성공 반환** | 반환값 보기 / `imencode` |
| 파일명 자리수로 자르기 | «시» 대신 «초» 를 읽음 | 정규식 |
| 도구가 개수로 id 부여 | `obj8` 이 둘 → «x 와 y 길이가 다르다» | 빈 번호 고르기 |
| 절반만 잘린 `.y16raw` | 정상처럼 읽히고 **−150 ℃** | 프레임 단위 검사 |

### 보정은 «나아질 때만» 적용할 것

상호상관이 1화소를 가리켜도 잡음일 수 있습니다. 되밀어 보고 적합도가
떨어지면 버리십시오. **재 놓고 무시하면 측정한 의미가 없습니다.**
