## 프로젝트 한 장 요약

### 무엇을 만드는가

폐쇄형 다단 수직농장은 층·구역별로 공조 편차가 생기는데, 종래에는 공간 대표
센서의 평균값으로 농장 전체를 일괄 제어해 국소 취약 구역의 작물이 스트레스를
받았습니다. 이 과제는 **작물 개체 단위로 VPD(수증기압차)를 측정하고
개체별 구동기로 맞춤 제어**하는 시스템을 만듭니다.

```
열화상 카메라 → 개체별 잎 영역 분할 → 개체별 엽온
                                        ↓
                    구역 온·습도 센서 → Leaf-to-air VPD 실시간 계산
                                        ↓
                    목표 범위 이탈 판정 → 개체별 송풍장치·구역 제어장치 가동
```

### 지금 하고 있는 것 *(2026-08-11 갱신)*

시스템의 첫 단추인 **"영상에서 개체별 잎 영역을 분할하는 것"** 입니다.

**가시광(RGB) 카메라가 2026-08-11 에 조기 도입되었습니다** (계획 2개월 선행).
이에 따라 전략이 바뀌어, 영역 식별을 **세 경로**로 두고 상황에 따라 전환합니다.

| 경로 | 방법 | 언제 쓰나 |
|---|---|---|
| A | 규칙 기반 RGB 분할 (ExG) | 명기, 지금 바로 |
| B | 고정 화분 격자 | 암기, RGB 부재 시 |
| **C** | **학습 기반 인스턴스 분할** | 명기·암기 모두. **PTZ·이동식 배치를 가능케 함** |

경로 C 의 핵심은 **명기 RGB 분할 결과를 열화상 좌표로 투영해 정답 마스크를
자동 생성**하는 것입니다. 사람 라벨링 없이 열화상 단독 분할 모델을 얻습니다.

> ⚠ **지금 당장 해야 할 한 가지** — 열화상 슬롯과 **같은 시각에 RGB 를 동시
> 녹화**하십시오. 현재 열화상(08-06∼09)과 RGB(08-11)는 시각이 어긋나 같은 장면
> 쌍이 하나도 없어 학습을 시작할 수 없습니다. 사유는 [status.md 1장](status.md).

### 왜 열화상 단독인가 (중요 — 대외 설명 시 이 논리를 쓰십시오)

~~"RGB+열화상은 선행연구가 많아서"~~ 는 심사에서 약한 논리입니다. 대신:

> **수직농장은 암기(暗期)가 하루의 25~33%를 차지하고, 그 시간에는 RGB 분할이
> 물리적으로 불가능합니다.** 암기 VPD 관리는 결로·병해 관점에서 특히 중요하고,
> 분석 결과 **야간이 엽온 오차에 가장 민감**합니다(±1°C에 VPD 35% 오차).
> 열화상은 조도와 무관하게 24시간 동작합니다.

자세한 근거는 [기획서 3장](leaf_segmentation_plan.md#3-전략-열화상-단독-접근의-재정의).

### 반드시 알아야 할 여섯 가지 숫자

| 숫자 | 의미 |
|---|---|
| **0.56°C** | 엽온 오차 예산. VPD 오차 0.1 kPa에 해당. 카메라 사양 ±2°C는 이것의 **3.6배** |
| **114 %** | 현재 계획의 오차예산 달성도 — **아직 목표 초과**. 습도 ±1 %·기온 ±0.2 ℃ 로 올리면 99 % ([status.md 2-11](status.md)) |
| **1.74°C** | 개체별 송풍의 잎−기온 온도차 저감량. 마커를 하나만 써도 1.62∼1.85 ℃ 로 유지되는 강건한 값 |
| **93%** | 마스크 precision 목표. IoU가 아니라 precision인 이유는 배경 화소 오염이 평균 엽온을 직접 끌어당기기 때문 |
| **182.6초** | 셔터(FFC) 주기. ±0.225°C 톱니파. 슬롯 3분(주기의 0.986배)으로 상쇄 완료 |
| **47.92 px** | 화분 격자 가로 피치 (화면 좌표). **.151 에서만 확정** — .152 에는 쓸 수 없음 |

> ⚠ **GSD 는 여전히 확정되지 않았습니다** (2.17~3.55 mm/화소).
> 현장이 삼각 거치대 경사 배치라 화면 행마다 깊이가 다릅니다.
> 과거 문서의 "3.4 확정", "2.17 확정"은 **모두 폐기된 값**입니다.
> 자세한 것은 [status.md 3장](status.md)과 [기획서 4-6](leaf_segmentation_plan.md).
>
> **★ 2026-08-28 — 카메라 상수는 확정됐습니다.** GSD 값 자체(화소 측정)는
> 그대로지만, 거기서 역산하던 **거리가 30 % 줄었습니다**:
> 일사센서 근거 457 → **320 mm**, 화분피치 근거 747 → **523 mm**.
> 아래 「카메라 상수」 절과 [distance_registry.md](distance_registry.md) 참조.
>
> **★ 550 mm 수수께끼는 해소됐습니다.** 그 값이 화분 평면까지의 거리라면
> 화분 피치가 178.8 mm 로 계산되어 실제 170 mm 와 **5 % 이내**입니다
> (구 상수로는 125 mm, 26 % 어긋남). 세 근거가 1.6 배씩 벌어지던 모순이
> 정리됐습니다. 원인은 **앞에 든 물체의 GSD 를 화분 평면 거리로 나눈 것**.

### ★ 카메라 상수 — 사양서가 틀렸습니다 *(2026-08-28 실측 확정)*

| | 사양서 | **실측** |
|---|---|---|
| 초점거리 | 208.4 px | **147.4 px** |
| 화각 | 42° × 32° | **57.0° × 44.3°** |
| 카메라 상수 k | 4.75 mm/px/m | **6.78 mm/px/m** |

**근거** — 서로 다른 두 거리(400·450 mm)에서 줄자로 잰 보드 거리가 계산값과
1.2 % 이내로 일치. 보정을 쓰지 않은 순수 기하(`f = 칸px × 줄자 / 30`)로도 같음.
자유 보정(168.8)은 20.6 %, 사양값(208.4)은 48.7 % 어긋남.

**물리 초점거리 2.52 mm 는 원래 맞았습니다.** 화소 피치가 17.1 µm 인데 사양서의
42° 는 12.1 µm 를 전제한 값입니다. 렌즈가 아니라 화각/피치 짝이 틀렸습니다.

> ⚠ **거리·GSD 가 들어가는 모든 계산을 다시 하십시오.** 특히
> `submit/산업재산권_심의자료_개체별VPD.md` 의 GSD 2.2 mm/px 와 거기서 나온
> 크라운 실치수·오차 예산 항목이 41 % 어긋납니다.

> ⚠ **사진만으로는 초점거리를 결정할 수 없습니다.** f 를 130~260 으로 바꿔도
> 재투영 RMS 가 3 % 밖에 안 변합니다(정면 자세 위주 + 보드가 화면 중앙에 머물면
> f 와 왜곡계수 k1 이 서로 상쇄). 그래서 도구에 `--focal 147.4` 로 외부
> 고정합니다. **이 인자를 빼면 기울임이 최대 3° 과대평가됩니다.**

### 현장 구성 (2026-08-11 확인)

**딸기** 수직농장. 개별 화분이 **삼각(A형) 거치대에 경사 배치**되어 흰색 홈통에
일렬로 놓여 있고, 잎과 화방이 홈통 바깥으로 늘어져 있습니다. 화분마다 개체
라벨(6-4, E-3 등)이 붙어 있습니다. LED 바 측면 조사, **점등 08:01 / 소등 18:01**.
이 경사 배치가 GSD 문제의 원인이자, 동시에 과제가 겨냥한 "국소 공조 편차"의
전형적 사례입니다.

**★ 2026-08-11, RGB 카메라가 계획보다 2개월 일찍 도입되었습니다.**
열화상 .151 바로 옆에 매직암으로 나란히 고정되어 있습니다(1920×1080, 30 fps).
**열화상에서 보이지 않던 화분이 RGB 에서는 선명히 보이므로**, 격자 등록·GSD
확정·라벨 자동생성이 모두 RGB 경로로 풀립니다.
자세한 진단은 [기획서 4-9](leaf_segmentation_plan.md).

## 환경 구축 (새 Ubuntu 22.04 PC)

```bash
# 1) TmSDK — .deb 와 .whl 둘 다 필요
#    https://github.com/ThermoEye/TmSDK/releases
sudo dpkg -i tmsdk-2.0.0-lib-Ubuntu-22.04-amd64.deb
pip3 install TmSDK-2.0.0-py3-none-manylinux2014_x86_64.whl

# 2) Python 패키지 — opencv 는 반드시 headless 판
pip3 install PyQt5==5.15.11 opencv-python-headless==4.13.0.92 numpy==2.2.6

# 3) 네트워크 — 카메라와 같은 서브넷에 고정 IP 필요
sudo ip addr add 192.168.0.100/24 dev enp7s0
ping -c 2 192.168.0.151

# 4) 확인
cd ubuntu_python_stream/
python3 scan_cameras.py
```

> ⚠️ `opencv-python`(headless 아닌 버전)이 깔려 있으면 PyQt5와 Qt 플러그인이
> 충돌해 실행되지 않습니다. 반드시 제거 후 headless로 교체하십시오.
> 그 외 트러블슈팅은 [ubuntu_python_stream/README.md 4장](../ubuntu_python_stream/README.md).

### 녹화 실행

```bash
cd ubuntu_python_stream/
python3 multi_cameras_multi_roi_y16.py
```

GUI에서 **예약 녹화 설정 → 시작 0시 / 종료 24시 / 반복 간격 20분 / 녹화 3분
→ 예약 시작**. ROI는 예약 시작 전에 그려두십시오(녹화 중에는 변경 불가).
ROI를 안 그려도 Y16 원본은 정상 저장되며, 온도는 사후에 임의 영역으로
계산할 수 있습니다.

### 데이터 확인

```bash
python3 read_y16.py info  raw_output/     # 프레임 수·온도 범위
python3 read_y16.py check raw_output/     # 품질 진단 (정기 실행 권장)
```
