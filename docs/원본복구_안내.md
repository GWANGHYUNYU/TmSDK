## 1. 무엇을 복사하면 되는가

**3차 촬영 원본 폴더 전체**를 주십시오. 지워진 65건만 골라내실 필요 없습니다.
이미 가지고 있는 68건은 **파일명의 시각으로 자동 건너뜁니다.**

```
D:\Coding_2025\TmSDK\incoming\th_260914\      ← 여기에 통째로
    th_260914_before\
    th_260914_350\  _400\  _500\  _600\  _700\  _800\  _1000\
    ...
```

| | |
|---|---|
| **필요한 파일** | `.y16raw` 와 `.y16meta` (짝으로) |
| 있으면 좋은 것 | `.avi` `.csv` — 없어도 됩니다 |
| **폴더 구조** | 원래대로 두십시오. 하위 폴더까지 알아서 훑습니다 |
| 용량 | 약 120 MB |

> ⚠ **`calib/` 에 덮어쓰지 마십시오.** 지금 정리된 68건이 들어 있습니다.
> `incoming/` 처럼 **별도 폴더**에 두시면 됩니다.

## 2. 그다음 제가 하는 것

```bash
python3 scripts/rescue.py incoming/th_260914            # 판정만
python3 scripts/rescue.py incoming/th_260914 --apply    # 살릴 것을 calib/ 로
```

녹화 하나에 약 25초, 65건이면 **30분쯤** 걸립니다.

### ① 코너 없이 보드 대비를 잽니다

7×4 가 안 잡혀도 **5×4 · 6×3 · 4×3 같은 작은 격자로 보드 위치만 찾으면**
거기서 검정 칸과 금속 칸의 온도차를 직접 잴 수 있습니다.

7×4 가 잡히는 52건으로 검증했습니다.

| | |
|---|---|
| 7×4 로 잰 대비 vs 작은 격자로 잰 대비 | **상관 r = 0.915** |
| 절대차 | **중앙 0.23 ℃** (상대오차 17 %) |

즉 **±0.2 ℃ 정도의 정확도로 대비를 말할 수 있습니다.**
보드를 아예 못 찾은 녹화는 그렇다고 따로 적습니다.

### ② 훨씬 집요하게 검출합니다

정규화 3종(p1-99 · p1-95 · 이상치클립) × **확대 ×1 · ×2 · ×3** × CLAHE.

**확대가 결정적입니다.** 원래 검출기는 확대를 시도하지 않았는데,
이 사다리를 걸어 보니 지금 가지고 있는 「부분격자」 16건 중
**12건이 7×4 로 승격**했습니다.

> 그래서 지워진 65건 중에도 **상당수가 살아날 가능성이 있습니다.**
> 다만 확실한 것은 원본을 봐야 압니다.

### ③ 판정

| 판정 | 뜻 |
|---|---|
| **살림(전체)** | 7×4 가 잡힘 — 그대로 캘리브레이션에 사용 |
| **살림(부분)** | 6×4 또는 7×3 이 2프레임 이상 — 자세·호모그래피에 사용 가능 |
| **못 살림** | 안 잡힘. **그때의 보드 대비를 ℃ 로 함께 적습니다** |

`--apply` 를 붙이면 살릴 것을 `calib/2026-09-14/thermal/` 로 복사하고,
`d0xxx_20260914_hhmmss` 규칙으로 이름을 붙입니다.

## 3. 이걸로 알게 될 것

지금 「3차 검출 실패의 원인은 보드 대비」라고 적어 두었지만, 근거는
**살아남은 68건과 2차 촬영과의 비교**뿐입니다
([status.md 0-B](status.md) 의 경고 참조).

원본이 오면 **탈락한 65건의 대비를 직접 재서** 확정할 수 있습니다.

| 만약 | 그러면 |
|---|---|
| 탈락분 대비가 1 ℃ 아래에 몰려 있다 | 「대비가 원인」이 **확정**됩니다 |
| 대비는 2~4 ℃ 인데 안 잡힌다 | 원인은 **다른 데** 있습니다 — 잘림·가림·흔들림을 다시 봐야 합니다 |

어느 쪽이든 [4차 촬영](confluence/열화상_캘리브레이션_4차_촬영표.md)의
「5~6자세마다 재가열」 지침은 유효합니다. 2차(4.06 ℃)와 3차(1.24 ℃)의
차이는 이미 측정된 사실이기 때문입니다.
