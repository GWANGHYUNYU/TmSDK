## 0. 왜 또 찍는가 — 남은 것은 **하나**입니다

세 번의 촬영으로 아래가 확정됐습니다.

| | 값 | 근거 |
|---|---|---|
| 열화상 초점거리 | **147.4 px** (화각 57.0° × 44.3°) | 줄자 + RGB 대조 |
| RGB 초점거리 | **1217 px** (화각 76.5° × 47.9°) | 427자세 자체보정 |
| RGB 왜곡 | k1 −0.3665 · k2 +0.1223 | 위와 같음 |
| 두 카메라 회전 | pitch 4.4° · yaw 4.7° · roll 6.9° | 91쌍 스테레오 |
| 캐노피 층 | 420 / 700 / 1000 mm | 줄자 |

**남은 것은 베이스라인 ‖T‖ 하나입니다.**

| | ‖T‖ |
|---|---|
| 캘리퍼스 실측 | 51.9 mm |
| 스테레오가 푼 값 | 58.1 mm |
| 녹화를 바꿔가며 다시 풀면 | **53.5 ~ 69.2 mm** ← 이게 문제 |

**왜 안 정해지는가**: 베이스라인은 **깊이가 달라질 때 정합이 어떻게 변하는지**로
결정됩니다. 그런데 RGB 와 열화상이 같이 찍힌 자료는 2026-08-28 뿐이고,
그때 판 거리가 **382~478 mm, 폭 96 mm** 밖에 안 됩니다.

3차(09-14)는 판 거리가 331~733 mm 로 넓었지만 **소등 뒤에 찍어 RGB 가
거의 안 겹칩니다** — 123건 중 RGB 와 짝지어진 것이 **1건**입니다.

> ### ⇒ 4차의 목표는 단 하나
> **소등 전에, 두 카메라가 동시에 찍히는 상태로, 깊이를 넓게.**
> 그러면 ‖T‖ 가 ±2 mm 안에서 정해지고 층별 정합이 끝납니다.

‖T‖ 가 6 mm 틀리면 최상단 캐노피(420 mm)에서 정합이 **2.1 화소** 어긋납니다.
크라운이 53 화소인 것을 감안하면 개체 경계에서 문제가 됩니다.

## 2. A. 스테레오 — 소등 전, 두 카메라 동시 ★ 최우선

### 먼저 확인

- [ ] **RGB 녹화가 실제로 돌고 있는가** — 파일이 생기는지 눈으로 확인
- [ ] 두 카메라 모두 같은 캐노피를 보고 있는가
- [ ] 노트북에서 `live_check` 가 돌고 있는가

```bash
python3 scripts/live_check.py <녹화폴더>                      # A-1 (30 mm)
python3 scripts/live_check.py <녹화폴더> --cell 50 --pattern 5x4   # A-2 (50 mm)
```

### A-1 · 30 mm 보드 (지금 쓰는 것) — 22자세

| 거리대 | 자세 수 | 칸 크기 | 비고 |
|---|---|---|---|
| 350 ~ 430 mm | 7 | 12 px | 최상단 캐노피 층 |
| 430 ~ 530 mm | 7 | 10 px | |
| 530 ~ 650 mm | 8 | 7 px | |

30 mm 보드는 **737 mm 가 한계**입니다 (147.4 × 30 ÷ 6 px). 그 너머는 A-2.

### A-2 · 50 mm 보드 (새로 만들 것) — 18자세

| 거리대 | 자세 수 | 칸 크기 |
|---|---|---|
| 600 ~ 750 mm | 6 | 10~12 px |
| 750 ~ 900 mm | 6 | 8~10 px |
| 900 ~ 1100 mm | 6 | 7~8 px |

### 자세 요령 — 세 가지만

**① 눕혀서 드십시오.** 화면 안에서 판을 굴리는 것(면내회전)은 손해입니다 —
보드만 작아지고 얻는 게 없습니다. **20° 이하로.**
3차에서 20° 넘는 자세가 10개 있었습니다.

**② 앞뒤로 기울이십시오.** 윗변을 카메라 쪽으로 눕히거나 반대로.
**20° 넘게 기울인 자세가 6개 이상** 있어야 합니다.

**③ 화면 여기저기에 두십시오.** 가운데만 반복하면 보정이 약해집니다.

> **판을 위아래로 기울이면 LED 반사도 같이 피해집니다.** 금속 칸이 거울이라,
> 윗변을 눕히면 금속면이 LED 바가 아니라 **바닥**을 비춥니다.
> 좌우로 돌리는 것으로는 이 효과가 없습니다.

### 판 관리 — 5~6자세마다 재가열 ★

3차에서 대비가 **75분에 걸쳐 1.62 → 0.91 ℃** 로 계속 떨어졌습니다.
한 번 데우고 끝까지 간 것입니다. 2차는 중앙 4.06 ℃ 였고 검출이 잘 됐습니다.

| | 지침 |
|---|---|
| 가열 위치 | **뒷면에서.** 앞면을 직접 데우면 칸마다 얼룩집니다 |
| 주기 | **자세 5~6개마다.** 가열 후 2~3분 안에 찍고 다시 |
| 목표 | **2 ℃ 이상**, 되도록 4 ℃ |
| 확인 | 눈짐작 금지. `live_check` 의 「대비」 칸을 보십시오 |
| 금지 | **냉각 금지.** 이슬점 18 ℃ 라 결로가 생기면 무늬가 통째로 사라집니다 |

**눈에 보이는 것과 열화상에 잡히는 것이 다릅니다.**
`docs/figures/05_촬영_대비기준.png` 에 5.8 / 2.6 / 1.4 ℃ 를 나란히
붙여 두었습니다. 1.4 ℃ 줄은 사람 눈으로도 무늬가 거의 안 보입니다.

### 한 자세를 찍는 법

1. 자세를 잡고 **2~3초 가만히** 있기 — 움직이는 중이면 두 카메라의 시각차
   몇 십 ms 가 몇 화소로 번집니다
2. 녹화 5초 이내로 끊기
3. `live_check` 가 `○` 또는 `△` 를 내면 다음 자세, `×` 면 다시

## 3. B. RGB 단독 — 왜곡 보강 (20자세)

**열화상과 동시일 필요 없습니다. 캐노피 앞일 필요도 없습니다.**
밝은 곳이면 됩니다. RGB 녹화만 켜고 찍으십시오.

### 왜 필요한가

지금 왜곡 계수는 **화면 반경 660 px 안쪽만** 자료로 뒷받침됩니다.
판이 화면 귀퉁이까지 간 적이 없어서(최대 반경의 76 %), 바깥 20 % 는 외삽입니다.
귀퉁이 보정량이 **416 px** 로 계산되는데 이 값은 믿을 수 없습니다.

### 무엇을 찍는가

- [ ] **네 귀퉁이 각각 3자세** — 판이 화면 모서리에 **걸치도록**
- [ ] 화면 중앙 4자세
- [ ] 상하좌우 변 중앙 각 1자세
- [ ] 각 위치에서 **기울여서도** 한 번씩

```
  ┌───────────────────────┐
  │ ■■              ■■ │   ← 귀퉁이가 핵심입니다
  │                       │
  │      ■   ■   ■      │
  │                       │
  │ ■■              ■■ │
  └───────────────────────┘
```

30 mm 보드로 충분합니다. 판을 데울 필요도 없습니다(RGB 는 명암만 보면 됨).

### 50 mm 보드 만들기

| | |
|---|---|
| 금속판 | STS304 또는 알루미늄, 코팅 없음, 0.8~1.0 mm · **300 × 250 mm** |
| 무광 흑색 | 무광 흑색 비닐테이프 또는 무광 흑색 스프레이 |

## 7. 돌아와서

```bash
# ① 전수 조사 — 무엇이 쓸 만한지
python3 scripts/inventory.py <새폴더>

# ② 정리 — 쓸 것만 남기고 날짜별로
python3 scripts/consolidate_calib.py --apply

    --max-dt 0.02 --max-blur 1.0 --cache

# ④ RGB 왜곡 재산출 (B 를 찍었다면)
python3 scripts/calib_rgb.py calib/<날짜>/rgb --out output/rgb_intrinsics2

# ⑤ 층별 호모그래피
python3 scripts/layer_homography.py output/rgb_verify/stereo.npz \
    --depths 420 700 1000
```

③ 에서 **‖T‖ 가 녹화를 바꿔도 ±2 mm 안에서 일정하면 확정**입니다.
지금은 53.5~69.2 mm 로 흔들립니다.
